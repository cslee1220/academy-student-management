# 모바일 실기기 점검 준비 및 UI 개선 현황

작성일: 2026-10-28 (갱신)

## 1. 작업 범위와 현재 상태

기존 UI 개선 문서 32~37의 결과를 현재 코드와 대조하고, 실제 Android·iPhone 점검을 위한 로컬 접속 조건과 통합 체크리스트를 정리했다.

- 로컬 Next.js와 replay Supabase만 사용한다.
- 원격 Supabase, migration, RPC/RLS, EC2, AWS 설정은 변경하지 않았다.
- `docs/23_windows_desktop_conversion_plan.md`는 기존 미추적 파일로 보존하고 수정·삭제·스테이징하지 않았다.
- 현재 확인된 P0 제품 오류는 없다.
- 실제 Android Chrome·iPhone Safari 검증은 아직 실행하지 않아 NOT VERIFIED다.
- 브라우저 viewport PASS는 실기기 PASS를 의미하지 않는다.

## 3. 실기기 접속 준비 결과

### 확인 결과

- PC LAN 주소: `192.168.0.74` (DHCP 환경에서는 변경될 수 있으므로 시작 전에 다시 확인)
- 개발 서버: `0.0.0.0:3000` 리슨 확인
- PC에서 `http://127.0.0.1:3000/api/health`: HTTP 200
- PC에서 `http://192.168.0.74:3000/api/health`: HTTP 200
- 실행 스크립트: `web/scripts/run-local-dev.mjs`
- Supabase: 서버가 로컬 Supabase 주소를 사용하며 휴대전화에 DB 포트를 공개하지 않음
- `APP_BASE_URL`: 로컬 설정에 없어 요청 origin을 사용함. LAN 주소로 접속해 초대 링크를 발급하면 LAN origin을 사용한다.
- HTTP 쿠키: 요청이 HTTP이면 Secure 쿠키를 사용하지 않고, HTTPS이면 Secure 쿠키를 사용한다. 이 동작을 완화하거나 우회하지 않았다.
- Windows Firewall: 3000 포트에 대한 명시적 허용 규칙은 확인되지 않았다. 방화벽 규칙을 자동으로 추가하지 않았다.

### PC 실행

이미 3000 포트가 실행 중이면 중복 실행하지 않는다. 서버가 꺼져 있을 때만 다음을 실행한다.

```powershell
cd "D:\Coding_basic\academy-student management\web"
npm run dev -- --port 3000
```

실행 스크립트가 원격 Supabase URL이나 위험한 `NEXT_PUBLIC_` 비밀값을 발견하면 시작을 차단한다.

### 휴대전화 접속 주소

PC와 휴대전화를 같은 신뢰할 수 있는 사설 Wi-Fi에 연결한 뒤 휴대전화에서 다음을 연다.

```text
http://192.168.0.74:3000/
```

`localhost`와 `127.0.0.1`은 휴대전화 자신을 뜻하므로 사용하지 않는다. 공유기 포트포워딩, 외부 터널, 공개 인터넷 노출은 사용하지 않는다.

### 합성 계정·데이터 준비

- 로컬 replay 환경의 합성 계정·fixture를 사용한다.
- 관리자·교사 계정은 저장소나 문서에 기록하지 않은 로컬 `.env.local`의 비공개 값을 사용한다.
- 보호자는 LAN 주소로 관리자 화면에 접속한 뒤 합성 학생의 보호자 접속 링크와 8자리 인증번호를 발급한다. 인증번호와 토큰은 채팅·문서·로그에 남기지 않는다.
- 기존 테스트 데이터는 AGENTS.md 규칙에 따라 자동 삭제하지 않는다.

### 접속 실패 확인 순서

1. PC와 휴대전화가 같은 Wi-Fi인지 확인한다.
2. PC에서 `ipconfig`로 LAN 주소가 `192.168.0.74`와 같은지 다시 확인한다.
3. PC에서 `http://192.168.0.74:3000/api/health`가 200인지 확인한다.
4. PC 개발 서버가 `0.0.0.0:3000`에 리슨하는지 확인한다.
5. 휴대전화에서 `http://192.168.0.74:3000/`으로 재시도한다.
6. 그래도 실패하면 Windows Firewall의 Private 네트워크 정책이 원인일 수 있다. 이때 범위를 `Private profile`, `LocalSubnet`, TCP 3000, 개발 서버 프로세스로 제한하는 임시 규칙을 별도 승인 후 검토한다. 기본 방화벽을 전체 해제하거나 공용 인터넷에 공개하지 않는다.

## 6. 실제 기기에서 남은 한계

- 현재 실행은 PC 자체의 LAN 주소 요청 200 확인까지만 수행했으며, 실제 Android·iPhone에서 주소를 연 결과는 아직 없다.
- 실기기에서는 가상 키보드, safe-area, 화면 회전, Safari 주소창, 실제 터치 스크롤을 별도로 확인해야 한다.
- HTTP LAN 환경은 운영 HTTPS 검증이 아니다. 운영 배포 전 HTTPS origin, Secure 쿠키, 초대 링크 origin, PWA 설치·업데이트 동작을 별도로 검증해야 한다.
- 오프라인은 오류 처리만 확인하며, 오프라인 저장·자동 재전송은 추가하지 않는다.
- 모바일 브라우저의 `beforeunload` 동작은 항상 보장되지 않으므로 실제 관찰 결과와 브라우저 한계를 구분한다.

## 7. 이번 작업 결과

이번 작업에서는 코드 변경 없이 현황 문서와 실기기 점검 준비를 완료했다. 기존 로컬 개발 서버는 LAN 접근이 가능하도록 같은 프로젝트의 개발 프로세스를 재기동했으며, 원격 DB·AWS·EC2·방화벽 규칙은 변경하지 않았다.

다음 점검은 전체 목록을 한 번에 수행하지 않고 `LAN 접속 → 로그인·보호자 인증 → 입력·저장 → 탐색·회전` 순서로 진행한다. 사용자가 전달한 결과는 `사용자 확인`으로 별도 기록하고 자동화 viewport 결과와 합치지 않는다.

## 8. 이번 요청의 추가 확인

- 기준 커밋 `564a5b9` 이후 현재 HEAD는 `b581535`이며, 작업 트리는 이 문서 이외에 기존 미추적 `docs/23_windows_desktop_conversion_plan.md`만 포함한다.
- 3000 포트가 `0.0.0.0`에 리슨하는 것을 재확인했다.
- PC에서 loopback 주소와 LAN 주소의 `/api/health`가 모두 HTTP 200이다.
