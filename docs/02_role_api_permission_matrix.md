# 역할별 API 권한표

## 1. 역할 정의

| 역할 | 코드 | 설명 |
|---|---|---|
| 시스템 관리자 | system_admin | 학원 등록·계정상태·서비스 장애 지원만 담당 |
| 학원 운영자 | academy_admin | 해당 학원의 운영·승인·통계·설정 담당 |
| 교사 | teacher | 현재 배정된 운영 블록·학생·과목의 날짜별 기록 담당 |
| 보호자 | guardian | 연결된 자녀의 저장된 날짜별 기록과 과거 공개완료 정보 조회 |

## 2. 공통 서버 검증 순서

모든 변경 요청은 아래 순서로 검사합니다.

1. 로그인·기기 세션 유효 여부
2. 소속 학원과 `academy_id` 일치 여부
3. 계정 활성 상태
4. 역할과 현재 담당 배정
5. 요청번호 중복 여부
6. 서버 버전값 일치 여부
7. 출결·필수입력·운영 블록 기간·요일 등 업무 규칙

화면에서 전달한 역할, 완료 여부, 시간, 학생 ID만으로 권한을 허용하지 않습니다.

## 4. 보호자 인증 API

| 기능 | 허용 대상 | 필수 조건 |
|---|---|---|
| 접속 링크 검증 | 링크 소지자 | 1회용·7일 이내·미만료·새 발급 시 이전 미사용 링크 취소 |
| 인증번호 확인 | 링크 검증 후 | 8자리 번호·5회 실패 시 15분 잠금 |
| 기기 등록 | 인증 완료 보호자 | 보호자당 활성 기기 1대 |
| 자녀 공개정보 조회 | 등록 기기 세션 | 보호자 연결·학생 재원·공개완료 또는 저장된 날짜별 기록 |
| 퇴원 시 접근 차단 | 학원 운영자 처리 | 연결·보호자 접근을 즉시 무효화하고 재발급 전까지 차단 |
| 기기 해제 | 운영자 또는 보호자 정책 | 세션·Push 구독 동시 무효화 |

## 5. 절대 허용하면 안 되는 요청

- 교사가 URL 또는 요청값만 바꾸어 다른 학생을 조회·수정하는 요청
- 보호자가 다른 학생 ID를 보내어 자료를 조회하는 요청
- 화면이 권한·학원·운영 블록 범위를 우회해 다른 학생을 저장하는 요청
- 학생 요청값으로 임의의 과목·교사·강의실·시간을 주입하는 요청
- 결석 학생의 테스트·5점 평가·나머지 저장 요청
- 보호자가 임시저장 또는 과목 일부만 최종저장된 날짜별 기록을 조회하는 요청
- 신규 날짜별 저장자료에 운영자 공개승인·교사 수정요청 대기 상태를 다시 추가하는 요청
- 시스템 관리자의 학습·비공개기록 본문 조회 요청
- `academy_id`가 다른 데이터의 조회·내보내기 요청

## 6. API 작성 원칙

- Route Handler 또는 서버 작업 함수에서 권한을 검사한다.
- 데이터베이스 RLS 정책을 함께 적용한다.
- 실패 시 `403 권한 없음`, `409 버전 충돌`, `422 업무 규칙 위반`처럼 이유를 구분한다.
- 오류 메시지에 다른 학생·학원·보호자의 개인정보를 포함하지 않는다.
- 모든 정정·승인·내보내기·중요 설정 변경에는 감사 또는 이력 행을 함께 만든다.
