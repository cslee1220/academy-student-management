# 학원별 수업기록 설정

## 범위

`/admin/academic`의 `수업기록 설정`에서 학원별 단일 양식을 관리한다. 관리자만 조회·변경할 수 있으며, 과목·반·교사별 상속 양식이나 자유 필드 편집기는 제공하지 않는다.

- 테스트 사용 여부와 기존 교사 수업기록의 과목·회차별 테스트 설정을 유지한다. 한 기록의 활성 테스트는 새 기록 기준 최대 2개다.
- 수업지표는 기존 5점 척도를 유지하며 활성 항목은 최대 4개다.
- 보충 유형은 기존 체크·예정일·완료·동시 수정 방지 흐름을 유지하며 활성 항목은 최대 3개다.
- 학생별 수업메모와 반 공통기록은 각각 사용/미사용만 설정한다.
- 출결은 설정 대상이 아니며 기존 입력·필수 검증·집계 규칙을 사용한다.

## 기본값과 적용

기존 학원의 최초 조회 시 기본 양식은 현재 동작을 보존하도록 멱등적으로 생성된다. 기본 지표는 `숙제`, `이해도`, `참여도`, 기본 보충 유형은 `테스트`, `숙제`이며, 메모·공통기록·테스트는 사용 상태로 시작한다. 빈 항목을 한도까지 채우지 않는다. 기존 학원별 설정 행이 있으면 덮어쓰지 않는다.

설정 변경은 새 수업기록부터 적용한다. 수업기록 저장 시 `daily_subject_records.record_form_snapshot`에 당시 사용 여부, 항목 ID·명칭·순서·만점·5점 척도를 저장하고, 동적 지표값과 보충 유형값은 별도 JSON으로 보존한다. 기존 고정 컬럼·테스트 정의/점수·보충 완료 version은 호환 경로로 계속 유지한다.

## 항목 보존과 한도 초과

항목 ID는 UUID로 저장하며 표시명이나 배열 위치를 식별자로 사용하지 않는다. 참조된 지표·보충 유형은 물리 삭제할 수 없고 사용 중지로 보존한다. 참조가 없는 미사용 항목만 삭제할 수 있다.

기존 기록이 테스트 3개 이상이거나 기존 양식의 활성 수가 새 한도를 초과해도 기존 초안·최종저장·공개 snapshot을 축소하거나 숨기지 않는다. 관리자 화면에 초과 상태를 안내하고, 한도 검증은 신규 양식과 신규 수업기록에 적용한다. 사용 중지된 항목은 과거 snapshot과 기존 미완료 보충에서 계속 조회·완료할 수 있다.

## 보충현황과 원본 수업메모 연결

보충현황의 `수업메모`는 학생의 가장 최근 메모를 임의로 가져오지 않는다. 보충 task의 학원·학생·수업 블록·수업일·과목·담당교사 연결을 기준으로 동일한 원본 `daily_subject_records`를 일괄 조회하고, 그 원본의 최신 저장 메모만 읽기 전용으로 표시한다. 원본 연결이 없거나 모호하면 다른 기록을 추정하지 않으며 기존 과제보충 내용은 보존한다.

수업메모와 기존 과제보충 내용은 별도 영역으로 함께 표시한다. 메모가 없으면 `등록된 수업메모 없음`으로 표시한다. 과거 보호자 공개 snapshot은 이 연동 조회로 재작성하지 않으며, 보호자 API는 기존 공개 조건을 통과한 자료만 반환한다.

보호자 홈과 학습 요약은 snapshot의 안정적인 지표 ID·당시 명칭·5점 척도를 사용해 새 지표도 항목별로 표시한다. 기존 숙제·이해도·참여도 평균은 기존 의미를 유지하고, 새 지표를 위험군 판정이나 기존 지표 의미에 임의로 합산하지 않는다. 교사 학습 이력도 당시 snapshot의 지표명과 긴 값을 줄바꿈해 표시한다.

## 권한·동시 수정·데이터베이스

설정은 학원 ID별로 격리되고 서버에서 관리자 권한과 활성 한도를 다시 검증한다. 설정 버전이 바뀐 뒤 저장하면 충돌로 거부하여 다른 관리자의 변경을 덮어쓰지 않는다. 설정 변경 이력과 감사로그를 남긴다.

스키마 변경은 `20261029080219_academy_lesson_record_settings.sql`과 제약 보정 migration에 기록되어 있다. 로컬 migration은 기존 행의 업무 값을 재작성하지 않고 설정 metadata와 snapshot 컬럼만 추가한다. 원격 Supabase에는 적용하지 않았다.

## 로컬 검증

다음 검증은 로컬 Supabase와 합성 fixture로 수행한다.

- `npx supabase migration up --local`
- `npx supabase db lint --local --fail-on error`
- `npm run lint`
- `npm run build`
- `npm run test:daily-integration`
- `git diff --check`

실제 휴대전화와 원격 Supabase·EC2는 이번 범위에서 검증하거나 변경하지 않는다.
