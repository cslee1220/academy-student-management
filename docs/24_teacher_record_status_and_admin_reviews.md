# 선생님 기록현황과 관리자 확인 표시

## 관리자 조회 기준

- 관리자 화면 경로는 `/admin/teacher-records`이다.
- 기본 조회는 `수업일 + 선생님` 기준이며, `수업묶음(선택)`은 같은 조회 행의 선택 필터다.
- 별도 수업묶음 조회 블록이나 학생별 검색·필터는 두지 않는다.
- 결과는 선생님별로 표시하고, 각 선생님 아래에 수업묶음을 자동 그룹화한다.
- 결과의 선생님 이름은 클릭 가능한 선생님 필터로 표시한다. 이름을 클릭하면 해당 선생님을 선택하고 수업묶음 선택을 초기화한 뒤 같은 수업일의 해당 선생님 기록만 재조회한다. 학생별 검색·필터는 제공하지 않는다.
- 수업묶음 중복 제거는 `class_id + subject_id + teacher_id + classroom_id + start_time + end_time` 기준을 기존 교사 수업 선택과 동일하게 사용한다. 같은 수업이 여러 요일에 운영되면 하나의 수업묶음으로 표시하고, 그룹 안에서는 조회일 요일의 원본 블록을 우선 사용한다. 같은 기준의 활성 중복 snapshot은 `effective_start`가 최신인 한 건을 대표로 사용하며 원본 행·수업기록은 삭제하거나 병합하지 않는다.
- 수업묶음은 수업일·요일·시간·강의실·과목 정보를 표시한다.
- 공통 수업내용과 공통 과제는 수업묶음 상단에 운영구분별로 한 번만 표시하고 학생별 행에는 반복하지 않는다.
- 화면 상단 종합 통계는 조회 결과에 포함된 유효 수업묶음이 있는 선생님을 분모로 사용한다. 수업 예정·기록 완료·작성 중·미기록은 각각 선생님 단위로 중복 없이 집계하고, 최종저장 완료·공개완료는 저장·공개 상태 축으로 별도 집계한다.
- 종합 통계의 인원 카드는 클릭할 수 있으며, 선택한 통계에 해당하는 선생님 명단과 수업묶음 수·대상 학생 수·작성·저장·공개 상태 요약을 표시한다. 명단의 선생님을 클릭하면 수업묶음 필터를 초기화하고 해당 선생님 기록으로 재조회한다.
- 학생 대상 수는 조회일에 날짜상 유효한 `class_schedule_block_students` 연결의 고유 학생 수로 계산한다. 휴원·휴직·퇴원 학생은 기존 기록을 읽기 전용으로 표시하되 입력 대상·기록 완료 분모에서는 제외하고, 미래 배정·대상 학생이 없는 수업·비활성 수업묶음은 조회에서 제외한다.
- 작성현황은 입력 대상 학생의 기록 존재 여부로 `미기록·작성 중·기록 완료`를 판정한다. 저장상태는 원자료의 `save_state`를 `미저장·임시저장·최종저장`으로 표시하며, 공개상태는 기존 `daily_record_publications`의 공개 조건을 기준으로 `비공개·공개대기·공개완료`로 분리한다. 따라서 작성 완료·임시저장과 공개완료는 같은 의미로 합치지 않는다.
- 선생님 또는 수업묶음의 마지막 저장 시각은 일괄 조회한 학생별 출결·수업기록과 공통 수업내용·과제의 `updated_at` 중 가장 최근 값이다. 목록마다 별도 API를 호출하지 않는다.

학생별 읽기 전용 기록에는 학생명·학번, 출결·결석 사유, 저장된 평가값, 테스트 결과, 테스트·숙제 보충 상태, 학생별 수업메모, 저장 상태, 보호자 공개 상태를 표시한다.

## 관리자 확인 표시

관리자 확인은 `daily_teacher_record_admin_reviews`에 학원·수업일·선생님 단위로 저장한다. 화면에는 선생님 그룹당 한 개의 확인 표시만 제공하며 수업묶음이나 학생별 확인으로 분리하지 않는다. 확인 표시의 저장·해제는 교사 최종저장, 공개, 정정 권한과 분리되며 공개 승인 절차로 사용하지 않는다. 확인 상태를 변경해도 `daily_record_publications`나 보호자 공개 snapshot을 수정하지 않는다.

기존 `daily_subject_record_admin_reviews` 테이블과 과거 행은 삭제·변환하지 않고 보존한다. 신규 관리자 확인 동작은 새 선생님 단위 테이블만 사용한다.

동시 수정은 확인 행의 `version`으로 검사한다. 기존 수업기록·평가·테스트·메모·공개자료는 삭제하거나 재작성하지 않는다.

## 보충현황 원본 연결

보충현황은 연결된 `student_supplement_tasks.source_subject_record_id`를 기준으로 원본 `daily_subject_records`를 한 번에 조회한다. 원본은 같은 학원·학생·수업 블록·과목·수업일일 때만 사용하며, 학생의 최근 메모를 추정해 가져오지 않는다. 수업메모는 읽기 전용으로 표시하고 없으면 `등록된 수업메모 없음`으로 표시한다.

기존 `homework_supplement_content`, `daily_subject_records.homework_supplement_content`, `student_supplement_tasks.homework_content`는 수업메모와 별도 영역인 `기존 과제보충 내용`으로 보존한다. 신규 보충 저장에서 내용이 없어도 기존 완료·예정일·동시 수정 구조는 유지한다.

## 적용·검증 범위

- 관리자 종합현황은 기존 `daily_teacher_record_admin_reviews`와 기록·공개 원자료를 재사용한다. 이번 데이터 보존·권한 보강에는 `20261029120701_harden_record_data_integrity.sql` migration이 필요하며 로컬에서만 적용·검증한다.
- 원격 Supabase migration, 운영 DB, EC2 배포에는 적용하지 않는다.
- 긴 학생별 메모와 표는 줄바꿈·내부 가로 스크롤로 확인한다.
- `360/390/768/1366px` 화면에서 관리자·교사 표를 확인하며 실제 휴대전화 검증은 제외한다.

## 운영 전 데이터 보존·권한 보강

- 일반 교사 저장은 제거된 과제보충 내용 필드를 보내지 않는다. 보충 task transaction은 기존 `homework_content`를 갱신하지 않고 task `version`을 잠금·검증하며, 불일치하면 과목기록 변경까지 함께 rollback한다. 신규 보충은 내용 없이 저장할 수 있고 기존 `homework_supplement_content` 및 `student_supplement_tasks.homework_content`는 보존한다.
- 학원별 기록 설정은 `save_academy_lesson_record_settings_transaction`에서 설정 행, `academy_setting_history`, `audit_logs`를 같은 transaction으로 저장한다. 설정·이력·감사로그 중 하나라도 실패하면 전체 변경을 rollback한다. 활성 지표 4개·활성 보충 유형 3개만 제한하고 비활성 과거 항목은 유지한다.
- 보호자 숙제 API는 `no_homework=true`인 공개 자료에서 `value_json.content`를 `null`로 반환한다. 내부 조회와 기존 DB 원문 및 공개 snapshot은 변경하지 않는다.
- 명시적 `blockId` 관리자 조회는 원본 블록이 비활성·기간 만료여도 학원·블록·학생·과목·기록일이 모두 일치하는 보존 기록을 조회한다. `blockId`가 없는 일반 날짜 조회는 기존 유효 블록 규칙을 따른다.
- `daily_teacher_record_admin_reviews`의 SELECT/INSERT/UPDATE RLS는 관리자 권한과 함께 `teacher_id`의 동일 학원 활성 교사 소속을 검증하며 `academy_id`·`teacher_id` 변경은 trigger로 차단한다. 관리자 확인은 공개 승인과 분리된다.
- 이 보강은 `web/supabase/migrations/20261029120701_harden_record_data_integrity.sql`에 기록했으며 로컬 migration만 적용·검증한다. 원격 DB와 기존 기록·공개 snapshot에는 적용하지 않는다.

## 남은 검증 기준

- 활성 수업지표는 최대 4개, 활성 보충 유형은 최대 3개로 제한하며 비활성 과거 항목은 보존한다. 재활성화 시 활성 개수를 다시 검증한다.
- 공통 숙제 저장 실패 후 재시도는 입력값과 `no_homework` 상태를 유지하고, 성공 응답을 받은 뒤에만 저장 완료를 표시한다. 중복 저장과 기존 원문 덮어쓰기를 허용하지 않는다.
- 보호자 API는 `no_homework=true`이면 `value_json.content`를 `null`로 반환하고, 내부 DB 내용과 공개 snapshot은 보존한다.
- 과제보충 저장은 `task_version`을 검증하며 충돌 시 저장을 거부한다.
- 기본 `npx supabase test db --local`의 Docker 네트워크 오류가 남으면 `--network-id`를 사용한 로컬 validation 결과를 별도로 기록하고 기본 명령은 PASS로 표시하지 않는다.
